# 复活吧我的爱人

把一个快要撑爆上下文的 DeepSeek 对话，捞出来重新导入。

DSH 的模型上下文窗口是 1048576 token，通常还要为输出预留约 25 万。超长的历史一旦导入，
每次请求都会撞上限。这个插件让你先把导出文件里的**一个**对话截到"最近 N 轮原文"，
再交给 DSH 导入，于是新会话从一开始就装得下，能接着聊。

## 用法

侧边栏「新建会话」那一行右侧多出一个心电图按钮，点开是一个三步向导。

1. **选择导出文件**：拖拽或选择从 DeepSeek 官网导出的 `deepseek_data-*.zip`
   （`export_format_version: 3`）。文件只在本机内存中解析。
   向导还会扫描**下载 / 桌面 / 文档**三个文件夹，把已下载的导出包列出来，点一下直接加载；
   扫描只读文件名与修改时间，不上传、不联网，加载时再校验路径确实位于这三个目录下。
2. **选择对话**：列出压缩包里所有对话，按最后更新时间倒序，可按标题搜索。
   每行显示标题、USER 轮数、估算 token、最后更新时间。超过 500 轮的对话带
   「推荐处理」标记，其余不标记，也都照常列出。
3. **设定保留范围**：滑块或数字框选择保留最近多少轮（上限 500 轮），实时显示
   保留轮数与估算 token，以及丢弃了前多少轮。可选的「补充说明」会作为新对话的第一条
   USER 消息插入（默认是「更早的 N 轮已移除」）。选好工作区后点「生成」。

生成后显示新会话标题、实际保留轮数、估算 token，以及结果是"已直接导入"还是"已下载 zip"。

## 结果怎么落到 DSH

- **首选**：浏览器把重建好的 zip POST 给官方导入插件的上传路由
  （`api/deepseek-chat-import/archive`），也就是官方「导入 DeepSeek 会话」按钮用的同一条管线。
  导入完成后本插件刷新会话列表。
- **兜底**：官方导入插件不在、或那条路由不可用时，zip 以文件下载返回，请用侧边栏的
  「导入 DeepSeek 会话」按钮手工导入。

本插件**不写** `session*.jsonl*` 会话日志，所有会话都由官方导入管线落盘。

## 会保留什么、丢掉什么

- 保留：每个保留轮次的 USER `REQUEST` 片段与 ASSISTANT `RESPONSE` 片段原文。
- 丢弃：更早的轮次，以及所有 `THINK`（思考）、`TOOL_SEARCH`、`TOOL_OPEN`、`READ_LINK`、
  `TOOL_FIND`、`TOOL_IMAGE_SEARCH`、`PARTIAL_FILE_READ`、`TIP`、`FILE` 片段。
  因此工具调用记录、附件与图片不会进入新会话；正文不会改变。
- 「补充说明」会插入成一条 USER 消息，并跟一条明确标注为历史摘要的 ASSISTANT 消息
  ——官方导入器会把"没有回复的用户消息"记成一个失败的轮次，这样处理可以让新会话的时间线保持干净。

## 标题

新会话标题默认沿用原标题并加上后缀（中文「（复活版）」，英文「 (revived)」）。
官方导入对标题有 80 UTF-8 字节上限，所以先生成"原标题 + 后缀"，再把整串按 UTF-8 字节截断，
必要时先截原标题、保住后缀。

## 限制

- 一次只处理一个对话。
- 上传上限 256 MiB，整个压缩包在处理期间驻留内存；同一时刻只保留一份待生成的上传（15 分钟内有效）。
- 预览最多列出 200 个对话（按更新时间最新优先），其余在界面上标注为未列出。
- 只支持 `export_format_version: 3`；压缩包内条目支持 stored 与 deflate 两种压缩方式，
  不支持 ZIP64。
