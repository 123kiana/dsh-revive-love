# 复活吧我的爱人（dsh-revive-love）

> **非官方插件。** 这是第三方作品，与 DeepSeek 官方无关。使用时需要 DSH 的官方「DeepSeek 会话导入」插件处于启用状态。

把一条快要撑爆上下文的 DeepSeek 对话捞出来，只保留最近若干轮，重新导入成一条能接着聊的会话。

DSH 的上下文窗口是 1048576 token，通常还要为输出预留约 25 万。历史一旦超长，每次请求都会撞上限；
这个插件让你在导入之前就把它截短，于是新会话从一开始就装得下。

## 安装

### 从 npm 安装（推荐）

```bash
pnpm add dsh-revive-love
```

或者在 DSH 插件页的 **Add plugin** 里直接填包名 `dsh-revive-love`。

装完**完全退出 DSH 再打开**（客户端模块在启动时加载，只刷新页面不够）。

### 从 GitHub Release 安装（不装包管理器时用这个）

1. 到 [Releases](../../releases/latest) 下载最新的 `dsh-revive-love-<version>-release.zip`
2. 解压得到 `dsh-revive-love` 目录
3. DSH → 插件页 → **Add plugin** → 选择这个目录
4. 完全退出 DSH 再打开

### 从源码安装（给要改代码的人）

```bash
git clone https://github.com/123kiana/dsh-revive-love.git
```

然后在 DSH 插件页 **Add plugin** 里选克隆下来的目录。

> 上面两种手动方式安装的都是本地目录依赖（`link:`），目录一挪动插件就失效。
> 想以后能用 `pnpm update` 升级，请走 npm 那条。

### 装之前先确认

官方「DeepSeek 会话导入」插件（`@deepseek-ai/dsh-deepseek-chat-import`）已启用。
本插件复用它把结果落盘；它不在时会退化成"下载 zip"，需要你手工导入。

## 依赖

- **需要**：`@deepseek-ai/dsh-deepseek-chat-import`（官方「DeepSeek 会话导入」插件）处于启用状态
- **需要**：`@deepseek-ai/dsh-api-session-controller`（会话列表刷新；增幅模式用它新建总结会话）

客户端另外注入 `@deepseek-ai/dsh-client-locale`、`@deepseek-ai/dsh-client-ui-renderer`、
`@deepseek-ai/dsh-client-ui-sidebar` 三个包，分别提供界面语言、渲染与侧栏挂载点。
它们都由 DSH 自带，不需要单独安装。

除此之外没有第三方依赖：只用 Node 内建模块，ZIP 读写与 CRC32 都是自己实现的。

## 用法

侧边栏「新建会话」右侧多出一颗心电图按钮，点开是三步向导：

1. **上传**：选择从 DeepSeek 官网导出的 `deepseek_data-*.zip`（`export_format_version: 3`）。
   如果导出包已经在你的**下载 / 桌面 / 文档**文件夹里，向导会自动把它们列出来，点一下就能加载，
   不用再手动选文件（纯本地扫描，不上传、不联网）
2. **选择对话**：列出压缩包里所有对话，按最后更新时间倒序，可按标题搜索。
   超过 500 轮的带「推荐处理」角标
3. **设定保留轮数**：滑块或数字框，上限 500 轮；可以填一句「补充说明」，它会成为新会话的第一条消息。
   开启增幅模式并拿到摘要时，摘要会取代这句补充说明，两者不会同时出现

点「生成」后，浏览器把重建好的 zip 交给官方导入管线，导入完成后自动刷新会话列表。

### 复活之后：模型怎么想起更早的事

开了增幅模式的会话，会带上两样东西：

- 摘要会作为**这个会话专属的系统提示词段落**出现，模型把它当成「我已经知道的背景」
- 被移除轮次的**逐字原文**存档在工作区，摘要末尾留一个指针指向它

模型需要确认「更早的时候到底怎么说的」时，会用工具 `history_search` 去搜存档：回复里带
命中总数、分布在哪几片、**最后一次出现在第几轮**，再给最多 5 段命中片段，合计约 2,300 字符
（≈1,500 token）；确认要看细节了才读那一片。要给几个候选词也行（空格分开，任一命中就算），
按第几轮找就直接传轮次号（如 `87`）。这个工具**只有复活过的会话才有**，普通会话的工具列表里
没有它。

存档里只有轮次号、**没有时间戳**，所以「上周三那次」这类按时间定位做不到。

## 配置

`index.js` 顶部几个常量：

| 常量 | 默认 | 含义 |
|---|---|---|
| `RECOMMEND_TURNS` | `500` | 超过这么多轮，列表里带「推荐处理」角标 |
| `MAX_KEEP_TURNS` | `500` | 向导里允许保留的最大轮数 |
| `HISTORY_BUDGET_TOKENS` | `790000` | 上下文窗口减去输出预留，用于超预算提示 |
| `MAX_ARCHIVE_BYTES` | `256 MiB` | 单次上传上限 |
| `MAX_ENTRY_BYTES` | `256 MiB` | 单个压缩包条目解压后的上限 |

## 边界

- 一次只处理一个对话
- 上传上限 256 MiB，整个压缩包在处理期间驻留内存；同一时刻只保留一份待生成的上传（15 分钟有效）
- 预览最多列出 200 个对话
- 只支持 `export_format_version: 3`，不支持 ZIP64
- 保留的是每轮 USER `REQUEST` 与 ASSISTANT `RESPONSE` 原文；思考、工具调用、附件、图片不会进入新会话
- **不写**任何 `session*.jsonl*` 会话日志，所有会话都由官方导入管线落盘

## 隐私

**默认完全本地：不联网、不收集任何数据。**

- 导出的压缩包只在**本机内存**里解析，裁剪后的结果交给本机 DSH 的官方导入路由落盘。
- 「已下载的导出包」扫描只读取下载 / 桌面 / 文档三个文件夹里匹配 `deepseek_data*.zip` 的**文件名与修改时间**，
  不读内容；点选时才读文件，并再次校验路径确实在这三个目录下。
- `history_search` 工具只读工作区 `.dsh-revive/` 里的存档文件，不联网、不调模型。
  被搜到的片段会进入该会话的上下文（也就是说会随之后的请求发送给你自己的 provider），
  这也是它把单次结果压在约 2,300 字符的原因。

### 唯一会联网的功能：增幅模式（默认关闭）

它在确认对话框里得到你的明确同意后才会启动，链路是：

1. 把**被移除的那 N 轮原文**写进当前工作区的 `.dsh-slim/` 临时目录（本地文件）
2. 在当前工作区新建一条总结会话，让 DSH 自己的 Agent 读取这些文件并生成摘要
3. 模型请求走 **你自己配置在 DSH 里的 provider 与账号**（例如你自己的 DeepSeek 账号）
4. 摘要返回后临时目录立即删除

**本插件没有自有服务器、没有遥测，不向作者或任何第三方传输数据。** 你选择不开增幅模式，就不会有任何模型请求。

> **导出文件里往往不只有你一个人的话。** 一段 DeepSeek 对话天然包含对方的发言，可能还有姓名、
> 联系方式等第三方个人信息。请先确认你有权处理这些内容；开启增幅模式意味着这些内容会被发送给你
> 所选 provider 的模型，请自行判断是否需要取得同意或先作匿名化处理。
>
> 增幅模式的内容去向由你和你的 provider 决定（包括可能发生的跨境传输）。本插件作者
> 不接收、不存储任何数据，不构成这些内容的个人信息处理者。

### 数据与删除

| 数据 | 存放位置 | 保留多久 | 怎么删 |
|---|---|---|---|
| 上传的导出包 | 仅进程内存 | 15 分钟后不可用，DSH 退出即消失 | 重启 DSH |
| 已下载包扫描结果 | 进程内存（文件名与路径） | 10 分钟 | 重新扫描或重启 |
| 增幅临时分片 | `<工作区>/.dsh-slim/summary-*/` | 运行结束/取消/失败后立即删除 | 残留时可手动删该目录 |
| 增幅诊断日志 | `<工作区>/.dsh-slim/last-run.log` | **不自动删除**，超过 256 KiB 时重置 | 手动删该文件 |
| 原对话存档 | `<工作区>/.dsh-revive/history-*/`（分片 + 索引） | **不自动删除** | 手动删该目录 |
| 总结会话 | 由 DSH 正常保存 | 不自动删除 | 像普通会话一样删 |

> `.dsh-revive/` 里是**逐字的原对话**，隐私浓度比摘要高。如果工作区是 git 仓库，建议把它
> 加进 `.gitignore`。

诊断日志只记时间、阶段、计数与会话 id，**不记录聊天正文**。它存在的唯一目的是增幅模式出错时
能看出卡在哪一步。

详见 [SECURITY.md](SECURITY.md)。

## 免责与风险

这个插件会**改写你的会话数据**，请先备份导出包，重要对话建议先导出原文件留档。

- 按现状提供，不作任何担保。作者不对数据丢失、会话损坏、导入失败、摘要错误、
  模型费用或额度消耗承担责任。
- 结果可能与你的期望不一致：标题会被改加后缀，思考与工具调用片段不会保留，
  一轮的尾巴可能因长度上限被截断。
- 会话列表异常、重复会话、残留临时文件都出现过（见 CHANGELOG）。遇到问题请保留
  `.dsh-slim/last-run.log` 并反馈。
- 增幅模式使用**你自己的模型账号**，产生的费用由你的账号承担。
- 本插件依赖 DSH 与官方导入插件未公开的内部接口，官方更新后可能失效，且不受官方支持。
- 原始导出包与旧会话不会被本插件修改，它只新增会话。
